# 🎧 TG Music App — v1.5.0

Telegram Mini App для музыкального канала: треки, опубликованные в канале, автоматически
появляются в приложении внутри бота. Тёмный минималистичный интерфейс с блюром, полноценный
плеер, избранное, история, профиль и панель управления для администраторов.

**Стек:** Python 3.12 · FastAPI · Telethon (MTProto) · SQLite3 · Vue 3 · Pinia · Vite · Docker · Amvera

## Что нового в 1.5

- **Плавный свайп плеера вниз.** Жест переписан: лист двигается за пальцем через `requestAnimationFrame`
  без перерисовки интерфейса, есть «мёртвая зона» (тап и горизонтальные жесты не дёргают плеер),
  обработка `touchcancel`. Закрытие продолжается **с того места, где отпустили палец**, и со скоростью жеста.
  Короткий медленный свайп мягко возвращает плеер на место. Во время жеста сезонный декор ставится на паузу.
- **Экран загрузки с фразами.** Если вход занимает дольше секунды, под логотипом появляются короткие фразы
  («Если место тебе нравится, ты захочешь в него возвращаться снова и снова… ⭐» и другие). Они всплывают
  из лёгкого размытия и растворяются, сменяя друг друга. Заставка встроена и в `index.html`,
  поэтому пустого экрана до загрузки скриптов тоже нет.
- **Просмотры альбомов.** У открытых альбомов виден счётчик 👁: один слушатель засчитывается не чаще
  раза в 12 часов, просмотры владельца не считаются. Значок есть и на карточках «Альбомов слушателей».
  У закрытого альбома счётчик скрыт (сервер его не отдаёт).
- **Управление пользователями** (Админка → Пользователи): поиск по имени, @username или ID, фильтры
  (Premium / заблокированы / с ограничениями) и карточка пользователя со статистикой, где можно:
  - задать **имя в приложении и боте** (2–24 символа, проверка на сервере; пусто — имя из Telegram);
  - выдать или забрать **Premium ⭐**;
  - **заблокировать**: доступ к приложению и боту закрывается сразу, даже с действующей сессией;
    альбомы пользователя скрываются, рассылки ему не отправляются;
  - **запретить альбомы** (создание, изменение, открытие доступа) и **запретить загрузку треков**.
  Пользователь получает уведомление в боте о каждом изменении (можно отключить) с необязательным
  комментарием администратора. Администраторов ограничить нельзя.
- **Premium ⭐:** переливающаяся рамка аватара, имя с плавным градиентом, мягкое «сияние» и искры
  в шапке профиля, карточка привилегий, золотистая окантовка аватара в таб-баре.
  Лимиты: **до 30 треков в заявке и 60 в сутки, до 150 альбомов** (у обычных пользователей — 5 / 10 / 50).
- **Исправления по итогам ревью кода:**
  - лимит одновременных потоков нельзя было обойти параллельными запросами — теперь место занимается
    до обращения к Telegram;
  - лимиты по IP вынесены в отдельный лимитер — поток запросов с поддельными адресами больше
    не может «вытеснить» лимиты пользователей; клики по рекламе считаются только для существующих объявлений;
  - суточный лимит заявок больше не обнуляется отменой или решением по заявке (отдельный журнал загрузок);
  - одобрение и отклонение одной заявки не могут выполниться одновременно, повторное «Отправить» не дублирует уведомление;
  - yt-dlp работает в собственных потоках: зависшая загрузка не блокирует обложки и аватары;
    редиректы при скачивании обложек проверяются на каждом шаге (защита от SSRF), некорректный порт в ссылке — не 500;
  - рекомендации: каталог кэшируется на всех, ранжирование вынесено из event loop;
  - бот не раскрывает название закрытого альбома по старой ссылке; рассылка, прерванная сбоем связи,
    помечается «Ошибка», а не «Готово»; ошибки получения аватара не дают 500;
  - поиск по имени в админке и заявках теперь регистронезависим и для кириллицы;
  - плеер: «Слушать» на уже играющем треке больше не ставит паузу; выключение перемешивания
    сохраняет правки очереди; «Далее» в конце очереди без повтора не перескакивает на первый трек;
    таймер сна обновляется; громкость не пишется в хранилище на каждое движение пальца;
  - интерфейс: опрос статуса в админке останавливается при уходе с вкладки, поиск не показывает
    устаревшие результаты, «Избранное» не зависает в скелетоне после сетевой ошибки, полоса перемотки
    анимируется через transform;
  - убраны дубликаты: единая публикация в канал с обработкой FloodWait, единое создание альбома с
    уникальным именем, общий `player.playAll`.

### Как устроены заявки (безопасность и ресурсы)

- Файлы **не скачиваются на хостинг**: они остаются в чате пользователя с ботом на серверах Telegram.
  Админ слушает их потоком напрямую из Telegram; при публикации документ пересылается в канал
  по ссылке на файл — без повторной загрузки.
- Принимается только mp3 (до 50 МБ и 20 минут); лимиты проверяются атомарно в БД;
  не больше 3 заявок на проверке у одного пользователя; черновики старше суток удаляются.
- Кнопки бота проверяют владельца заявки; тексты экранируются; теги — только буквы/цифры/«_».
- Эндпоинты модерации и прослушивания — только для `ADMIN_IDS`.

## Возможности

**Приложение**
- Главная: карусель **«Новинки»** (недавно опубликованные треки), блок **«Популярное»**
  (по прослушиваниям за 30 дней), теги (`#rock`, `#рок` из подписи поста), лента всех треков с бесконечной прокруткой.
- **Плеер**: play/pause, следующий/предыдущий, перемотка (drag), буферизация, перемешивание,
  повтор (всё / один трек), громкость (на десктопе), очередь (играть следующим, добавить, удалить),
  таймер сна, лайк, «поделиться» и «открыть пост в канале», свайп вниз для закрытия,
  управление с экрана блокировки (Media Session API), восстановление последнего трека.
- **Поиск** по названию / исполнителю / тегу (регистронезависимо, включая кириллицу), недавние запросы, подборки.
- **Моё**: избранное и история прослушиваний, «Слушать» / «Перемешать».
- **Профиль**: аватар из Telegram, имя, @username, дата первого входа в бота и сколько дней с нами,
  личная статистика. Для администраторов — кнопка **«Панель управления»**.

**Панель управления** (только `ADMIN_IDS`, проверка на сервере)
- Пользователи (всего / сегодня / за неделю), DAU / WAU / MAU, прослушивания, треки, лайки, длительность библиотеки.
- График прослушиваний за 14 дней (+ табличный вид), топ недели.
- Синхронизация канала (быстрая / полная), статус подключения бота, размер БД и превью.
- Управление треками (скрыть / показать), список пользователей.

**Бот**
- `/start` — выбор языка (при первом запуске) и приветствие с кнопкой открытия приложения;
  кнопка меню настраивается автоматически и подписывается на языке пользователя.
- `/language` — сменить язык.
- `/upload` — предложить свои треки (mp3, до 5 за раз и 10 в сутки; Premium — 30 и 60).
- `/stats` — краткая статистика (админам), `/sync` — полная синхронизация канала (админам).

## Как это работает

```
Канал ──(новый пост)──▶ Бот (Telethon, MTProto) ──▶ SQLite (метаданные + превью обложек)
                                   │
Mini App (Vue) ──HTTPS──▶ FastAPI ─┴─▶ /api/stream/{id}: байты читаются из Telegram
                                        блоками и сразу отдаются плееру (Range, перемотка)
```

- **Аудиофайлы не хранятся на хостинге.** Сервер проксирует поток из Telegram «на лету»
  (с поддержкой HTTP Range), на диск ничего не пишется. Через MTProto нет лимита Bot API в 20 МБ.
- На хостинге лежат только **превью обложек** в WebP (160 и 600 px, ~10–40 КБ) и база SQLite.
- Обложка берётся из встроенной в аудио миниатюры; если её нет — из фото-поста, опубликованного
  прямо перед аудио (в течение 5 минут). Иначе показывается красивый градиент.
- При первом запуске бот сам импортирует **всю историю канала**; дальше новые, изменённые и
  удалённые посты синхронизируются автоматически.

## Деплой на Amvera

1. **Бот**: создайте у [@BotFather](https://t.me/BotFather) (или используйте существующий) → `BOT_TOKEN`.
2. **API ID / HASH**: [my.telegram.org](https://my.telegram.org) → *API development tools* → `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`.
3. **Добавьте бота в администраторы канала** — иначе бот не получит посты. Для раздела «Контент»
   (публикация треков ботом) включите боту право **«Публикация сообщений»**.
4. **Amvera** → «Создать проект» → тип *Приложение*, окружение **Docker**. Загрузите файлы
   проекта (через интерфейс или `git push`). Конфигурация уже лежит в `amvera.yml`:
   сборка по `Dockerfile`, порт `3000`, постоянное хранилище `/data`.
5. **Переменные** (вкладка «Переменные»; токены и hash лучше добавить как *секреты*):

   | Переменная | Пример |
   |---|---|
   | `BOT_TOKEN` | `123456789:AA...` |
   | `TELEGRAM_API_ID` | `1234567` |
   | `TELEGRAM_API_HASH` | `0123456789abcdef...` |
   | `CHANNEL_USERNAME` | `@my_music` (или `my_music`, или `https://t.me/my_music`) |
   | `ADMIN_IDS` | `111111111,222222222` |
   | `WEBAPP_URL` | `https://<проект>-<логин>.amvera.io` — домен из вкладки «Домены» |
   | `SECRET_KEY` *(необязательно)* | длинная случайная строка для подписи сессий |
   | `WEBAPP_SHORT_NAME` *(необязательно)* | короткое имя Mini App из `/newapp` в BotFather |
   | `YTDLP_PROXY` *(необязательно)* | прокси для YouTube: `http://…`, `socks5://…` |
   | `YTDLP_COOKIES` *(необязательно)* | путь к cookies.txt YouTube, например `/data/cookies.txt` |

6. Нажмите «Собрать». После запуска бот сам выставит кнопку меню. Напишите боту `/start`.

> Свой Telegram ID для `ADMIN_IDS` можно узнать, например, у [@userinfobot](https://t.me/userinfobot).

### Ссылки «Поделиться» сразу в приложение

Чтобы ссылка на трек/альбом открывала мини-приложение **сразу** (с плеером или альбомом),
включите основной Mini App бота: @BotFather → *Bot Settings → Configure Mini App → Enable Mini App*
и укажите тот же `WEBAPP_URL`. Бот определяет это автоматически при запуске
(ссылки вида `t.me/<бот>?startapp=…`). Альтернатива — создать приложение через `/newapp` и задать
переменную `WEBAPP_SHORT_NAME` (ссылки `t.me/<бот>/<short_name>?startapp=…`).

Без этой настройки ссылка ведёт в бота: он присылает сообщение с кнопкой, которая открывает
приложение уже с нужным треком или альбомом.

## Безопасность

- **Авторизация**: подпись Telegram `initData` проверяется на сервере (HMAC-SHA256 с токеном бота,
  сравнение за постоянное время, проверка срока годности 24 ч, запрет дублирующихся ключей).
  Далее выдаётся короткоживущий (12 ч) токен сессии, подписанный отдельным ключом; хранится только в памяти.
- **Права администратора** определяются только на сервере по `ADMIN_IDS` при каждом запросе.
- **SQL** — только параметризованные запросы; `LIKE`-шаблоны экранируются.
- Валидация всех входных параметров (pydantic, ограничения длины/диапазонов, regex для тегов),
  лимит размера тела запроса 32 КБ, детали ошибок не раскрываются.
- **Rate limiting**: авторизация, API, поиск, лайки, прослушивания, стриминг;
  ограничение одновременных потоков (3 на пользователя, 24 на сервер) — защита слабого хостинга.
- Заголовки: строгий **CSP** (скрипты только свои + `telegram.org`, `frame-ancestors` только Telegram),
  `nosniff`, `Referrer-Policy: no-referrer`, HSTS, `Permissions-Policy`, CORP.
- Токен бота и токены сессий **не попадают в логи** (access-лог отключён, httpx/telethon — только WARNING).
- Защита от path traversal при раздаче файлов, защита от «декомпрессионных бомб» в Pillow.
- Swagger/OpenAPI отключены. CORS не включён — API доступно только с собственного домена.
- Контейнер работает от **непривилегированного пользователя** (`setpriv`, `no-new-privs`),
  каталог данных `0700`, один процесс uvicorn.
- Скрытые треки не отдаются ни в списках, ни в стриминге.
- **Альбомы**: название нормализуется (NFKC, пробелы), разрешены только буквы любых алфавитов, цифры,
  пробел и `! # & ' ( ) , + - . : ? _`; запрещены эмодзи, `< > / \ " ` и невидимые символы
  (zero-width, bidi), «мусорные» повторы; длина 1–32; уникальность без учёта регистра и пробелов;
  лимит проверяется атомарно в транзакции. Чужие альбомы недоступны по id; поделиться можно только
  по случайному коду (не угадывается перебором id).
- **Реклама и рассылка**: только `https://`-ссылки без логина/пароля в URL, ограничения длины, HTML
  рассылки проверяется перед отправкой; управление — только администраторам.
- **Режим обслуживания** проверяется на сервере для всех запросов и стриминга, а не только в интерфейсе.

## Локальный запуск

```bash
# бэкенд
cd backend && python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export $(grep -v '^#' ../.env | xargs) DATA_DIR=./data
uvicorn app.main:app --port 3000

# фронтенд (в другом терминале; /api проксируется на :3000)
cd frontend && npm ci && npm run dev
```

Mini App работает только внутри Telegram (нужен `initData`). Для теста снаружи используйте
HTTPS-туннель и укажите его адрес в `WEBAPP_URL`.

Docker:

```bash
docker build -t tg-music-app .
docker run -d -p 3000:3000 -v $(pwd)/data:/data --env-file .env tg-music-app
```

## Раздел «Контент» (YouTube Music → канал → приложение)

Используется для **собственного контента** (или контента, на публикацию которого у вас есть права).

1. Вставьте ссылку на трек, альбом или плейлист (`music.youtube.com`, `youtube.com`, `youtu.be`).
2. Просмотрите треки (по 10 на странице) и выберите: один трек, текущую страницу или всё.
3. По желанию: «Создать альбом в приложении» (название проверяется как у обычных альбомов)
   и подпись к постам (например, хэштеги — они станут тегами в приложении).

Как устроено (для слабого хостинга):
- yt-dlp загружается в память только при использовании раздела;
- одно задание и один трек одновременно, пауза между постами (лимиты Telegram);
- скачивается готовая дорожка **m4a/AAC без перекодирования** — ffmpeg не нужен, CPU почти не тратится;
- файл пишется на диск во временный каталог и **удаляется сразу после публикации**; обложка
  загружается отдельно и сохраняется только как превью;
- уже опубликованные треки не загружаются повторно (но попадают в созданный альбом);
- yt-dlp ограничен экстракторами YouTube — произвольные адреса не обрабатываются (защита от SSRF).

> ⚠️ YouTube может ограничивать запросы с серверов хостингов («Sign in to confirm you’re not a bot»)
> или работать медленно в некоторых регионах. В этом случае задайте `YTDLP_COOKIES`
> (экспорт cookies.txt из браузера, файл положите в постоянное хранилище `/data`) и/или `YTDLP_PROXY`.
> Для разбора ссылок YouTube yt-dlp нужен JS-движок **Deno** — он устанавливается автоматически
> вместе с зависимостями (`yt-dlp[default,pin-deno]`).

## Обновление с прошлых версий

Просто разверните новую версию: база данных мигрирует автоматически при запуске
(данные пользователей, треки, лайки и статистика сохраняются).

## Примечания

- Работает один процесс (`--workers 1`): Telegram-сессия и лимиты живут в памяти процесса.
- Боту недоступен `getHistory`, поэтому история импортируется запросом сообщений по id пакетами по 100.
- Прослушивание засчитывается после 30 секунд (или половины короткого трека); повтор того же трека
  тем же пользователем в течение 10 минут не учитывается.
